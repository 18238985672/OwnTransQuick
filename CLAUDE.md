# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Own翻译 is a Windows-only desktop quick-translation tool written as a single Python file (`app.py`). It runs in the system tray. When the user selects text in any app and presses the selection hotkey (default `Ctrl+Alt+1`), it simulates `Ctrl+C`, waits for the clipboard to change, sends the text to the NiuTrans (小牛翻译) text translation API, and shows a popup (bottom-right of the screen by default, or wherever the user last dragged it). A second hotkey (default `Ctrl+Alt+2`) translates the current clipboard as-is. Both are configurable in settings. Japanese translations get a kana reading line below them (pykakasi). UI text and user-facing docs are in Chinese.

## Commands

```powershell
python -m pip install -r requirements.txt   # pinned deps: requests, pystray, Pillow, pykakasi, pyinstaller
python app.py                               # run from source
.\build.ps1                                 # build dist\Own翻译.exe (one-file, windowed; bundles pykakasi data via --collect-all)
```

`build.ps1` first renders the exe icon to `build/logo.ico` with `app.save_logo_ico` and the version resource to `build/version.txt` with `app.write_version_file` (from `APP_VERSION`), then builds with PyInstaller under the ASCII name `OwnTranslation` and then renames the output to `dist\Own翻译.exe`. The build fails at the rename step if `Own翻译.exe` is currently running, so quit it from the tray first (a one-file exe runs as two processes; stop both). `build/`, `dist/` and `*.spec` are build output and git-ignored.

Releases: bump `APP_VERSION` in `app.py`, run `build.ps1`, and publish `OwnTranslation-vX.Y.Z-win64.zip` (containing `Own翻译.exe`) on GitHub Releases with its SHA256. Keep the asset name ASCII; GitHub mangles non-ASCII asset names. `docs/images/` holds the README logo and screenshots; they are not used by the app and are regenerated by hand with sample data (never a real API key or user paths).

There are no tests or linters configured.

## Architecture (app.py)

- **Startup** (`__main__`): `setup_logging` (warnings/errors and uncaught exceptions from the main thread, worker threads and Tk callbacks go to `%APPDATA%\NiuTransQuick\log.txt`, rotated; never log the API key or translated text) → `acquire_single_instance` (named mutex; a second launch shows a message box and exits) → `enable_dpi_awareness` (system DPI aware) → `TranslatorApp`.
- **Threads**: Tk mainloop runs on the main thread; `pystray` runs on a daemon thread; `HotkeyManager` runs a Win32 message loop on its own thread and calls the hotkey callbacks there; each translation request runs on a daemon thread. Anything touching Tk widgets from another thread must go through `self.root.after(0, ...)`.
- **DPI scaling**: the process is DPI aware, so Tk geometry is in physical pixels. Every pixel literal (sizes, padding, wraplength, offsets) goes through `self.s(...)`, which scales 96-DPI values by `self.scale`; font point sizes scale on their own. Use the `Own.TCheckbutton` ttk style for checkboxes, because the classic tk indicator does not scale.
- **Hotkeys**: two config keys, `hotkey` (copy selection, then translate) and `clipboard_hotkey` (translate clipboard), defaults in `DEFAULT_HOTKEYS`, callbacks in `self.hotkey_callbacks`. `HotkeyManager` registers them with Win32 `RegisterHotKey` on its message-loop thread (WM_HOTKEY is delivered to the registering thread, so `set` posts `WM_APP_SET_HOTKEYS` and waits); a digit also registers its numpad key. It replaced a `keyboard`-library low-level hook, which Windows silently removed after sleep so the hotkeys died; do not go back to a hook. `set` keeps the old hotkeys and returns a message on failure (e.g. `ERROR_HOTKEY_ALREADY_REGISTERED` → 已被其他程序占用), surfaced through `apply_hotkeys`/`self.hotkey_error`. Hotkey strings look like `ctrl+alt+1` (`parse_hotkey`; modifiers in `HOTKEY_MODIFIERS`, main key a letter, digit or F1–F24). Key state comes from `GetAsyncKeyState` (`key_down`, `pressed_modifiers`) and Ctrl+C is sent with `send_ctrl_c`. The settings page records hotkeys with `hotkey_recorder`: registered hotkeys swallow their keys, so recording calls `suspend_hotkeys` and stopping calls `resume_hotkeys`; the main key comes from the Tk event's virtual-key code via `vk_to_key_name`.
- **Hotkey flow**: `on_hotkey` (listener thread, must return fast or key state stops updating) → `copy_selection_worker` (thread: waits until none of the hotkey's keys is held so the target app doesn't receive e.g. Ctrl+Alt+C, backs up every memory-based clipboard format with `backup_clipboard`, records `GetClipboardSequenceNumber`, sends `ctrl+c`, polls until the sequence number changes (toast via `show_toast` if nothing was copied), reads the text with `read_clipboard_text` and puts the user's clipboard back with `restore_clipboard`; these Win32 helpers use `self.clipboard_hwnd` because `SetClipboardData` needs a window-owned clipboard) → `capture_clipboard_and_translate` (main thread, reads clipboard via Tk, toasts if it holds no text; resets source to 自动识别 and picks the default target with `detect_language`: 中文 → 日本語, anything else → 中文) → `start_translation` → `translate_worker` → `finish_translation`.
- **Translation**: `start_translation` always re-reads the (editable) original text box and silently truncates it to `max_chars` (setting, capped at `NIUTRANS_MAX_CHARS`) unless that exact text is already cached, since the limit only protects API credits (this keeps a long translation intact when swapped back); the status line notes the truncation. Character counters sit in the bottom-right of both cards: `update_original_count` (driven by `<<Modified>>`, shows count / limit, red when over) and `set_result_text(..., is_translation=True)`. Each request gets an incrementing `request_id`; `finish_translation` ignores results whose id is no longer current. Successful results go into an in-memory LRU `self.cache` keyed by `(source, target, text)`, where an auto-detected source is stored as the detected language (the API still gets "auto"), and the reverse direction `(target, source, translation) -> text` is cached too, so swapping never re-requests; cache hits skip the API and are not added to the daily character count. `swap_languages` swaps source/target (resolving 自动识别 via `detect_language`) and makes the last successful translation the new original text.
- **Theme**: all colors come from `THEMES["light"|"dark"]` via `self.c`; never hard-code colors in widgets. `system_theme` reads the Windows app theme; `refresh_theme` (called when the popup or settings is opened) restyles ttk and rebuilds the popup if it changed, and `set_title_bar_theme` switches the native title bar.
- **Logo**: `make_logo(size)` draws the logo with Pillow (blue gradient tile, circular-arrow "O" around 译; sizes <= 24 drop the ring). It is cached and used for the tray icon, every window's title-bar icon (`root.iconphoto(True, ...)`), the settings sidebar and the About page; `save_logo_ico` writes the multi-size .ico for the exe. The app itself ships no image assets.
- **Settings window**: `show_settings` builds a Windows 11-style layout: a sidebar of canvas-drawn nav items (icons from the Segoe Fluent Icons font, falling back to Segoe MDL2 Assets) switching between pages 常规 / 快捷键 / 翻译 / 统计 / 关于, each made of rounded white cards (`card`, drawn on a canvas behind an inner frame), `option_row`s with canvas `toggle` switches, and a shared 保存/取消 footer. Nothing is applied until 保存; validation errors switch to the page that has the problem.
- **Popup**: `show_popup` builds the window once and afterwards only re-shows it (closing/`Esc` just withdraws it). A `<FocusOut>` binding calls `close_if_focus_left`, which hides the popup when no window of the program has focus (`app_has_focus`), unless the 图钉 pin (`self.pinned`) is on, the `close_on_click_outside` option is off, or it was shown less than `FOCUS_OUT_GRACE` ago; Esc and close-after-copy work regardless of the pin. `fit_popup` sets each text box's height from its wrapped line count (`MIN_TEXT_LINES`..`MAX_TEXT_LINES`) and sizes the window to its requested height. Placement: if the user has dragged the popup, its top-left corner and width are saved as config `popup_position`/`popup_width` (detected by `remember_user_position`, which compares the window with `self.placed_geometry` on every refit and on hide) and reused; otherwise it sits in the bottom-right corner of the work area of the monitor at `monitor_point` (the mouse when a translation starts). It is always clamped to that monitor's work area (`get_work_area`), accounting for the title bar and borders with `frame_offsets` because Tk geometry excludes them. `frame_offsets` must use Tk coordinates only (`winfo_rootx/rooty` minus `winfo_x/y`): DWM frame bounds are physical pixels and, on a monitor whose scale differs from the system DPI, made the popup drift off-screen. Settings → 常规 → "恢复到右下角" calls `reset_popup_position`. The toast and the settings window use `get_work_area` too. The footer is packed with `side="bottom"` before the cards so the buttons stay visible when the window is small.
- **API**: `request_translation` uses a fixed `REQUEST_TIMEOUT` (10 s; an old `timeout` config value is dropped on load) and raises `TranslationTimeout` on timeout. `translate_worker` retries every other `TranslationError` once after `RETRY_DELAY`. `request_translation` posts to `https://api.niutrans.com/NiuTransServer/translation` with `from`/`to`/`apikey`/`src_text` and raises `TranslationError` with a user-facing Chinese message for network/HTTP failures. `extract_translation` handles both a plain-string `tgt_text` and nested dict responses, and maps non-zero `error_code`s through `NIUTRANS_ERRORS`. The settings "测试 API Key" button reuses `request_translation`.
- **Kana readings**: `kana_reading` (pykakasi, loaded lazily by `get_kakasi` and warmed up on a background thread at startup) turns Japanese text into its reading: kanji words become hiragana, existing kana and other characters stay as-is. It converts line by line because pykakasi duplicates words around newlines. `set_result_text` appends the reading on its own line below the translation (Google Translate style) with the `kana` tag, and `fit_popup` adds a line of room for it; `self.translated_text` stays plain, so copying never includes it.
- **Config**: `%APPDATA%\NiuTransQuick\config.json` (the directory name is kept for compatibility with older versions). It stores the API key, both hotkeys, close-after-copy, show-kana, max chars, always-on-top, and a per-day count of successfully translated characters (reset when the date changes).
- **Autostart**: stored only in the registry (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `Own翻译`), not in config. `get_autostart` reads it back, and startup rewrites the command so it follows the exe if it was moved.
- **Tray menu**: "显示上次翻译" (the default item, so a left click on the icon reopens the last popup), settings, pause/resume hotkey (`self.paused`), quit (stops the hotkey thread, which unregisters the hotkeys, stops the tray, destroys the Tk root). The tray tooltip (`tray_title`) is three lines: name + `APP_VERSION`, then each hotkey.
